================================================================================
           دليل نقل وتجهيز وتشغيل نظام كاشيرك ERP على جهاز جديد
                         (Waitress WSGI + SQLite)
================================================================================

يقدم هذا الملف دليلاً شاملاً وسريعاً لتشغيل النظام على أي جهاز كمبيوتر جديد
بسهولة تامة وبضغطة زر واحدة.

--------------------------------------------------------------------------------
1. هل ينفع نسخ مجلد البيئة الافتراضية (venv) مباشرة؟
--------------------------------------------------------------------------------
الجواب: لا، لا يُنصح بنسخ مجلد venv إطلاقاً.
السبب: مجلد venv يحتوي على مسارات مطلقة ثابتة تخص الجهاز القديم، ونقله يتسبب في
أخطاء تعطل الأوامر.
الطريقة الصحيحة: انسخ ملفات المشروع فقط (بدون venv)، واستخدم سكريبت التجهيز
التلقائي setup_venv.bat المرفق لينشئ بيئة جديدة في ثوانٍ.

--------------------------------------------------------------------------------
2. البرامج المطلوبة على الجهاز الجديد
--------------------------------------------------------------------------------
1) لغة Python (إصدار 3.10 أو 3.11 أو أعلى):
   - تحميلها من الموقع الرسمي: https://www.python.org/downloads/
   - [هام جداً]: أثناء التثبيت، ضع علامة صح أمام "Add Python.exe to PATH" أسفل الشاشة.

2) قاعدة البيانات:
   - تم ضبط النظام ليعمل افتراضياً على قاعدة بيانات SQLite (الملف db.sqlite3).
   - لا تحتاج إلى تثبيت أي برامج أو سيرفرات قواعد بيانات إضافية!

3) متصفح إنترنت (Google Chrome أو Microsoft Edge أو Firefox).

--------------------------------------------------------------------------------
3. الملفات التي يجب نقلها والتي يجب استبعادها
--------------------------------------------------------------------------------
[الملفات والمجلدات المطلوبة للنقل]:
- مجلد apps
- مجلد config
- مجلد templates
- مجلد static و media
- ملف db.sqlite3
- ملف requirements.txt
- ملف manage.py
- ملف .env
- ملف setup_venv.bat
- ملف start_server.bat

[المجلدات التي يجب حذفها وعدم نقلها]:
- مجلد venv
- مجلدات الكاش __pycache__
- مجلد .git

--------------------------------------------------------------------------------
4. خطوات التجهيز والتشغيل (الطريقة التلقائية بضغطة زر - الأسهل)
--------------------------------------------------------------------------------
الخطوة 1: انسخ مجلد المشروع إلى الجهاز الجديد.

الخطوة 2: اضغط مرتين على ملف:
          setup_venv.bat
          - سيقوم السكريبت تلقائياً بإنشاء بيئة العمل venv وتثبيت جميع المكتبات
            المطلوبة وتجهيز قاعدة البيانات SQLite وملفات الواجهة.

الخطوة 3: لإنشاء حساب المدير (الأدمن) لأول مرة:
          افتح موجه الأوامر (CMD) داخل مجلد المشروع واكتب:
          python manage.py createsuperuser
          ثم أدخل اسم المستخدم، البريد، وكلمة المرور.

الخطوة 4: لتشغيل السيرفر في أي وقت:
          اضغط مرتين على ملف:
          start_server.bat
          ثم افتح المتصفح واكتب:
          http://localhost:8080

--------------------------------------------------------------------------------
5. خطوات التجهيز اليدوي عبر موجه الأوامر (CMD / PowerShell)
--------------------------------------------------------------------------------
إذا أردت كتابة الأوامر بنفسك:
1) إنشاء البيئة الافتراضية:
   python -m venv venv

2) تفعيل البيئة:
   venv\Scripts\activate.bat

3) تثبيت المكتبات:
   pip install -r requirements.txt

4) ترحيل قاعدة البيانات وتجميع الملفات الثابتة:
   python manage.py migrate
   python manage.py collectstatic --noinput

5) إنشاء حساب الأدمن:
   python manage.py createsuperuser

6) تشغيل السيرفر عبر خادم Waitress:
   waitress-serve --port=8080 --threads=8 config.wsgi:application

--------------------------------------------------------------------------------
6. فتح النظام من أجهزة أخرى في نفس الشبكة المحلية (LAN)
--------------------------------------------------------------------------------
إذا أردت فتح النظام من كاشير فرعي أو تابلت في نفس المحل/الفرع متصل بنفس الراوتر:

1) معرفة عنوان IP الجهاز الرئيسي:
   - افتح موجه الأوامر واكتب: ipconfig
   - ابحث عن سطر IPv4 Address (مثال: 192.168.1.50).

2) السماح بالمنفذ في جدار الحماية (Windows Firewall):
   - افتح Windows Defender Firewall with Advanced Security
   - اختر Inbound Rules ثم New Rule
   - حدد Port واكتب 8080، ثم اختر Allow the connection واضغط حفظ.

3) الدخول من أي جهاز في الشبكة:
   - افتح المتصفح واكتب:
     http://192.168.1.50:8080
     (استبدل 192.168.1.50 بـ IP الجهاز الرئيسي لديك).

--------------------------------------------------------------------------------
7. التبديل إلى PostgreSQL مستقبلاً (اختياري)
--------------------------------------------------------------------------------
إذا أردت مستقبلاً تشغيل النظام على قاعدة بيانات PostgreSQL بدلاً من SQLite:
- افتح ملف .env
- غيّر السطر:
  DB_ENGINE=sqlite
  إلى:
  DB_ENGINE=postgresql
- قم بإلغاء علامة التعليق (#) عن بيانات الـ DB_USER و DB_PASSWORD و DB_NAME.
- سيتحول النظام تلقائياً للعمل بنظام الـ Multi-Tenant المخصص للشركات.

--------------------------------------------------------------------------------
8. ملفات التشغيل السريع (.bat)
--------------------------------------------------------------------------------
- setup_venv.bat       : إنشاء بيئة venv وتثبيت/تحديث المكتبات.
- setup_database.bat   : إنشاء .env تلقائياً لو مش موجود + الميجريشن + شجرة الحسابات
                         + إنشاء حساب مدير (لو مفيش). لا يغيّر أي باسورد موجود.
- start_server.bat     : تحديث المكتبات لو ناقصة + الميجريشن + النسخ الاحتياطي التلقائي
                         (لو مفعّل) + collectstatic + تشغيل السيرفر.
- switch_database.bat  : التبديل بين SQLite و PostgreSQL وفحص الاتصال.
- backup_database.bat  : نسخة احتياطية. مع PostgreSQL يعرض قائمة:
                           [رقم] سوبر ماركت واحد  |  [A] كل السوبر ماركتات
                           [F] نسخة كاملة لقاعدة البيانات (للنقل لجهاز جديد)
- restore_database.bat : الاستعادة بنفس القائمة.
- schedule_backup.bat  : جدولة مهمة ويندوز يومية الساعة 02:00 للنسخ الاحتياطي التلقائي
                         (شغّله مرة واحدة، ويفضل "Run as administrator").
- run_tests.bat        : تشغيل الاختبارات الآلية.

--------------------------------------------------------------------------------
9. نقل النظام لجهاز جديد (PostgreSQL)
--------------------------------------------------------------------------------
على الجهاز القديم : backup_database.bat ← اختار [F]
                    انسخ الملف من backups\_full\ + ملف .env
على الجهاز الجديد : 1) انسخ المشروع + ملف .env + ملف النسخة إلى backups\_full\
                    2) setup_venv.bat
                    3) switch_database.bat (اختار PostgreSQL)
                    4) restore_database.bat ← اختار [F] ← اختار الملف ← اكتب YES
                    5) start_server.bat
ملحوظة: لو SECRET_KEY في .env مختلف عن الجهاز القديم، استعادة نسخ السوبر ماركت
الفردية من سطر الأوامر هتطلب كتابة TRUST للتأكيد (الواجهة ترفضها للأمان).

--------------------------------------------------------------------------------
10. النسخ الاحتياطي التلقائي اليومي
--------------------------------------------------------------------------------
1) من إعدادات النظام (لكل سوبر ماركت): فعّل "نسخ احتياطي تلقائي يومي" وحدد
   "عدد النسخ التلقائية المحفوظة" (الافتراضي 7).
2) الأمر:  venv\Scripts\python.exe manage.py auto_backup
   - يمر على كل سوبر ماركت (PostgreSQL) أو قاعدة SQLite الحالية.
   - ينشئ نسخة موقّعة باسم auto_backup_... لو آخر نسخة تلقائية أقدم من 23 ساعة
     (أو مفيش)، والخيار --force ينشئ نسخة فوراً.
   - يحتفظ بآخر N نسخة تلقائية فقط ويحذف الأقدم (مع ملف .sig).
     النسخ اليدوية (من صفحة النسخ الاحتياطي) لا تُحذف أبداً.
   - الملفات في backups\<اسم مساحة العمل>\ (SQLite: backups\default\) وتظهر في
     صفحة النسخ الاحتياطي ويمكن تنزيلها/استعادتها منها.
3) يعمل تلقائياً عند تشغيل start_server.bat (لو فشل لا يمنع تشغيل السيرفر).
4) لتشغيله يومياً حتى لو السيرفر شغال طول الوقت: شغّل schedule_backup.bat مرة
   واحدة؛ ينشئ مهمة "MasarERP AutoBackup" في Task Scheduler الساعة 02:00.
   - تشغيلها الآن للتجربة :  schtasks /Run /TN "MasarERP AutoBackup"
   - إلغاء الجدولة        :  schtasks /Delete /TN "MasarERP AutoBackup" /F
   - المهمة تعمل والمستخدم مسجّل دخول والجهاز شغال في هذا الوقت.
ملحوظة: انسخ مجلد backups بشكل دوري على فلاشة أو جهاز آخر؛ النسخة على نفس
الهارد لا تحمي من تلف الهارد.
